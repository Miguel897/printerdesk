## 1. Summary

Turn PrinterDesk (formerly ScanDesk) from a scan-only tool into a **complete app for the home
printer**: scan, print and copy (scan, then print). Printing works like scanning already does: the
app talks **directly to the printer over the network**, with **no HP software and no printer
driver**, using the open
**IPP Everywhere / AirPrint / Mopria** protocols that the HP ENVY 6432e supports.

The user can print the scanned document or any PDF/image file, and choose **color or black & white,
one or two-sided (automatic duplex), rotation/orientation, paper size and type, quality, copies and
page range**.

## 2. Background and findings

Tested on 2026-10-18 against the ENVY 6432e (`192.168.1.130`, firmware `VASPYTPP2N001.2628C.00`).
Probe scripts and the full attribute dump are in `draft/tools/ipp-probe/` (local, not committed).

duplex, the app sends the back page **rotated 180°**. (Short edge: send as is — matches CUPS
`rastertopwg`; not yet tested on paper.)

**Decision:** printing is feasible without any driver. The print layer is built on **IPP**, with the
Windows print queue as a later fallback for other printers (§9).

## 3. Goals

1. Print the **current scanned document** or an **opened PDF / image** in a few clicks.
2. Choose **color / black & white**, **one-sided / two-sided** (long or short edge), **orientation /
   rotation**, paper size and type, quality, copies and page range.
3. **Copy**: scan from feeder or flatbed and print straight away, with the same options.
4. See **printer status and ink level**, job progress, and cancel a job.
5. Keep v1 principles: no driver, no HP software, LAN only, single exe.

### Non-goals (v2)

- Printing from other apps through PrinterDesk (i.e. PrinterDesk as a Windows printer/virtual driver).
- Printer setup/admin (Wi-Fi config, firmware, EWS settings) — link to the printer's web page instead.
- Fax, HP+ / cloud printing, ePrint.
- Printing Office documents (Word/Excel) — print them to PDF first.
- Printers without IPP (P2 fallback via Windows queue, §9).

## 7. Technical design

### 7.1 Pipeline

```
Document pages (scan JPEGs, PDF pages, images) + per-page rotation
  → page range / n-up / orientation (auto-rotate to sheet)
  → render each page to a bitmap at print resolution (300 dpi normal, 600 dpi best)
  → color: sRGB 8-bit, or gray 8-bit for B&W
  → back pages rotated 180° when long-edge duplex and sheet-back = rotated
  → encode as PWG raster (P0) or PCLm (P1, JPEG strips — smaller for photos/scans)
  → IPP Print-Job (streamed, chunked HTTP) with sides, print-color-mode, media-col,
    print-quality, copies, print-scaling
  → poll Get-Job-Attributes until completed / aborted / canceled
```

The printer has no PDF support, so the **app always rasterizes**. This is the same model used by
Mopria, Android and CUPS for this class of printer.

### 7.2 Stack additions

| Concern | Choice | Notes |
|---|---|---|
| IPP client | **Own code** over `HttpClient` (encoder/decoder ~400 lines), like the eSCL client | Alternative: [`SharpIppNext`](https://www.nuget.org/packages/SharpIppNext) (MIT, .NET Standard, IPP 1.0–2.2). Own code keeps dependencies low and is already proven by the probe; decide at M5 (Q2). |
| PWG raster / PCLm encoder | Own code (~150 lines each) | Format documented in PWG 5102.4 / Mopria PCLm spec; PWG raster encoder proven in T5. |
| PDF page rendering | **PDFium** via `bblanchon.PDFium.Win32` (native `pdfium.dll`, BSD-3/Apache-2.0) + own thin P/Invoke wrapper (~300 lines, `LibraryImport`), on **one dedicated render thread** (PDFium is not thread-safe) | Same wrapper approach already proven and published in a sibling app. Renders with `FPDF_PRINTING` (+ `FPDF_ANNOT` so filled forms print) straight to a print-resolution bitmap. Alternatives in §9 / Q3. |
| Preview | **Own rendering** (PDFium for PDF pages, JPEG decode for scans) into WPF images — **replaces WebView2** | Needed anyway so the preview shows print effects (gray, rotation, n-up, F51); also fixes the v1 "full preview PDF rebuilt on every change" cost and drops the WebView2 dependency and its profile folder. |
| Image ops | WPF `BitmapSource` / `TransformedBitmap`, `FormatConvertedBitmap` (Gray8) | Rotation, scaling, gray conversion without new packages. |
| Discovery | Existing Zeroconf, add `_ipp._tcp` | |

### 7.3 Solution layout

```
src/PrinterDesk.Core
├─ Escl/            (existing)
├─ Ipp/             IppClient, IppEncoder/Decoder, PrinterCapabilities, PrintJob, PrinterStatus
├─ Printing/        PrintOptions, PageImposer (range, n-up, auto-rotate, duplex back flip),
│                   PwgRasterWriter, PclmWriter
└─ Documents/       page model gains a source type: ScanJpeg | PdfPage | Image
src/PrinterDesk.App
├─ Pdfium/          PdfiumNative (P/Invoke), PdfiumDocument, PdfiumThread
src/PrinterDesk.App
└─ ViewModels/PrintViewModel, page/preview view models (WebView2 removed)
```

Logic stays in Core (imposition, IPP, raster writers, document operations) so view models stay thin
and everything that matters is unit-testable.

### 7.4 Document model

v1 pages are JPEG files with a rotation. v2 adopts an **immutable document state** with
**undo/redo**:

```
Document
├─ Sources: [ Source { Id, Kind: ScanJpeg | Image | Pdf, Path/Bytes, PdfiumDocument? } ]
├─ State:   DocumentState (immutable record)
│    └─ Pages: [ PageItem { Id, SourceId, PageIndex, Rotation } ]
└─ Undo / redo: stacks of DocumentState snapshots (max 200); dirty = State ≠ last saved/printed snapshot
```

- Edits (reorder, delete, rotate, import) are **pure functions** on the state (`PageOperations`);
  no PDF is built until Save or Print.
- **Opened files are read once into memory** (`FPDF_LoadMemDocument64`): no file locks, and the
  document prints/saves exactly the bytes that were opened.
- Crash recovery (v1 F27) keeps working: scan JPEGs stay in the session folder; the state is
  serialized next to them.
- **Save**: scan JPEGs embedded without recompression (as v1); PDF pages **imported as vector**
  with PDFsharp (`PdfDocumentOpenMode.Import`), user rotation as `/Rotate`; written to a temp file
  and moved over the target (atomic). Note: PDFsharp import drops `/AcroForm`, so form fields of an
  opened PDF are not interactive in the saved copy (values stay visible).

### 7.5 Data size and speed

A4 at 300 dpi = 2480 × 3508 px (26 MB RGB uncompressed). PWG raster run-length encoding makes text
pages small (T5: 2 pages with color bars = 385 KB) but photo-like scans stay large (~10–20 MB/page),
which is fine on a LAN but slow on Wi-Fi. PCLm with JPEG strips fixes that (P1). The printer prints
~10 ppm B&W, ~7 ppm color; rendering and sending must stay ahead of it (stream page by page).

### 7.6 Dependency trust

Only one new shipped package. Assess any further package the same way before adding it:

| Package | Use | Assessment |
|---|---|---|
| `bblanchon.PDFium.Win32` | PDF rendering | Binary build of Google's PDFium (Chrome's PDF engine, fuzzed by OSS-Fuzz), built in public GitHub Actions; NuGet-verified prefix; ~9 M downloads; tracks Chromium weekly. Single-maintainer native binary → pin exact version (CPM + lock files, `RestoreLockedMode` in CI), review Dependabot PRs by hand, keep it current (it parses untrusted PDFs). Fallback: `Windows.Data.Pdf`. |
| `SharpIppNext` (not adopted) | IPP client | MIT, active. Not needed if the own IPP code stays small (Q2). |
| `PDFtoImage`, `Docnet.Core` (rejected) | PDFium wrappers | Pull in SkiaSharp (+~10 MB) / unmaintained since 2023. |

Removed: `Microsoft.Web.WebView2` (preview replaced, §7.2).

After the change: update `draft/tools/make-notices.sh` (PDFium licenses come from the matching
`bblanchon/pdfium-binaries` release archive, `licenses/`, since the NuGet package has none; convert
Latin-1 files such as `freetype.txt` to UTF-8), regenerate `THIRD-PARTY-NOTICES.txt`, update the
README license paragraph, and run `dotnet restore --force-evaluate`.

### 7.7 Security

v2 parses two kinds of untrusted input, so security gets explicit treatment:

- **PDF files from anywhere** → PDFium kept current (§7.6); render on a dedicated thread; a
  corrupt/encrypted file shows a clear error (password prompt P2) instead of crashing.
- **Network responses** (IPP, eSCL) from any device on the LAN → the IPP decoder bounds every
  length field, the total response size and collection depth, and rejects malformed data; tests
  include truncated and oversized fixtures.
- Add **`SECURITY.md`** (GitHub private vulnerability reporting, latest release only supported).
- Print jobs carry `requesting-user-name` = Windows user name only if the user opts in; default
  "PrinterDesk" (no personal data sent to the printer's job log).

### 7.8 Build, distribution and release

Keep v1's single self-contained exe, CPM + lock files, warnings-as-errors, MinVer, CHANGELOG-driven
release notes. Add:

- **App manifest**: PerMonitorV2 DPI awareness and long-path support (v1 has no manifest), so
  previews are sharp on high-DPI screens.
- **Release integrity**: publish `SHA256SUMS.txt` and a **build provenance attestation**
  (`actions/attest-build-provenance`, SHA-pinned) with every release; README explains
  `Get-FileHash` and `gh attestation verify`. Release-day check of the local copy includes both.
- Exe size: +~5 MB for `pdfium.dll`, −WebView2 SDK; target ≤ 75 MB.
- Code signing, installer with auto-update (Velopack), winget: tracked in the release-readiness
  notes, not in this PRD; required before a broad public launch of 2.0.

## 9. Out of scope / alternatives considered

- **Windows print queue** (`System.Printing` + XPS `PrintTicket`, or `PrintDocument`): works for any
  installed printer and gives landscape via the driver, but needs the printer installed on each PC
  and gives less control over status and job progress. Capabilities verified (§2.2), no print test
  yet. **Candidate P2 fallback** for printers without IPP.
- **Raw port 9100 / PCL**: needs HP's proprietary PCL3GUI raster. Rejected.
- **Sending JPEG directly** (`image/jpeg`): one image per job and `multiple-document-jobs-supported = false`,
  so no duplex across pages. Possible fast path for single-page photo printing (P2).
- **URF (AirPrint raster)**: equivalent to PWG raster; PWG is the open, documented one.
- **`Windows.Data.Pdf`** for rendering: zero payload, but needs a Windows-SDK TFM and gives no
  control over form/annotation rendering. Fallback only.
- **WebView2 preview** (v1): cannot show print effects and rebuilds a full PDF on every change. Replaced.
- **iText, MuPDF**: AGPL. Rejected.

## 12. Verification plan

Each milestone ends with on-device prints in draft quality, mostly white pages to save ink.
The black cartridge on the test printer is very low, so on-device tests use **color** by default and
B&W only once (B&W may come out faint; that is the cartridge, not the app).

| Check | Expected |
|---|---|
| 3-page duplex long edge, color | 2 sheets, backs upright when turned like a book |
| 1 page B&W (`monochrome`) | printed without color ink (faint is acceptable while black is low) |
| 2-page duplex short edge | backs upright when flipped up |
| Landscape page, Orientation Auto | page rotated to fill the portrait sheet, text reads bottom-to-top |
| Page range `2-3`, 2 copies collated | 2× pages 2,3 in order |
| Cancel after page 1 | printer stops, job state `canceled` |
| Remove paper mid-job | status shows "out of paper", job resumes after reloading |
